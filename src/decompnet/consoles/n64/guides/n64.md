# N64 facts that help

Memory
- 0x80000000-0x807FFFFF: RAM (KSEG0, cached). 0xA0000000+: the same RAM uncached (KSEG1).
- 0xA4000000-0xA4FFFFFF: hardware registers (video VI 0xA4400000, audio AI 0xA4500000, peripheral PI
  0xA4600000, serial SI 0xA4800000). Code that pokes these is driver/OS code.
- The game's code is loaded from the ROM to RAM at boot (the "main" segment). Big games load more code
  later, to an address of its own (Super Mario 64's engine, Rare's and Nintendo's compressed code). The
  app finds that code too and splits it with the rest; each function has its own address.

The OS library
- Games link Nintendo's OS library (libultra): threads, message queues, DMA, controller input, the
  scheduler. Its functions use recognizable patterns (disabling interrupts with `mfc0`/`mtc0`, TLB and
  cache instructions). Try locally indexed library signatures and source before spending model calls
  reconstructing known SDK routines. A signature suggests an identity; only a compile/link byte match
  verifies the C.
- The ROM header's library revision is a hint. Individual components can come from different revisions
  or local patches. Count distinct functions, not matching archives: the same routine often appears in
  several releases and in both standard and retail libraries.
- For GCC libultra comparisons, preserve the version's character signedness. The local reconstruction
  Makefile uses `-funsigned-char` through 2.0J and omits it for 2.0K. Test the target bytes rather than
  assuming a later release's flags apply to older components. Change a function's compiler range only
  after an exact verdict, and keep existing-match regression checks enabled.
- Reconstructed source can contain game-specific edits. Compare rebuilt objects with an original local
  archive when available; record every original object retained as a fallback. Do not present that
  member as rebuilt from the source tree. See `docs/local-sdk-comparisons.md` for the comparison workflow.

Graphics and audio
- Display lists are arrays of 64-bit commands built in memory: long runs of stores of constants with
  0xE7000000, 0xFD..., 0x06000000-like high words are display list building, usually through macros.
- Audio and graphics microcode (RSP code) is data, not MIPS code you decompile.

Compilers
- First-party games mostly use IDO (5.3 for early titles, 7.1 later). Many third-party games use GCC
  2.7.2 from KMC. A few use SN Systems' GCC variants.
