# Matching SN Systems N64 code

SN64 GCC 2.8.1 and the 2.7.2 builds 0001, 0004 and 0006 are separate toolchains with their own code generation and assembler behavior. Select the build that matches the game's instructions; a near miss is not proof that a different build was used.

The original packs run their pinned preprocessor, compiler and ASN64 assembler under wibo. A pinned PsyQ-to-ELF converter lets the normal N64 linker judge the result. The converter is built once at installation and needs a C++20 compiler and zlib headers (Xcode Command Line Tools on macOS; g++ and zlib1g-dev on Linux or WSL). Installing original packs requires explicit acceptance of their proprietary license.

The reconstructed `sn-n64-272-970404` profile runs native cpp and cc1, the pinned modern-asn64 compatibility pass and GNU binutils. Its default `-fno-exceptions` avoids the reconstruction's exception-enabled default for C. On macOS it builds from pinned source with Xcode Command Line Tools; Linux uses a pinned release. This reconstruction is a comparison option, not proof that it reproduces an original SN build.

Keep compiler flags and source context fixed while testing candidates. The normal linked-byte judge decides whether a function matches.
